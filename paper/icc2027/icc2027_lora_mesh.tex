\title{MeshEcho: Confidence-Aware Route Admission for LoRa Mesh IoT}

\author{
\IEEEauthorblockN{Gao Zu \quad Quan Zhi}
\IEEEauthorblockA{Shenzhen University, Shenzhen, China}
}

\maketitle

\begin{abstract}
LoRa mesh IoT networks trade source-confirmed reliability against scarce
airtime. Flooding adds redundancy but creates collisions, whereas a cached
source route can select a weak multi-hop path. We present MeshEcho, a
confidence-aware route-admission policy with bounded recovery, and evaluate
it with a reproducible packet-level simulator. Version 2.1.22 uses matched
candidate exposure, independent reception streams, a distinct min-hop
baseline, and explicit generalization cases. In the calibrated 50-node,
8.25-km matrix over 20 seeds, MeshEcho reaches 0.720 ACK-confirmed
completion at 28.1 s airtime, versus 0.502/38.5 s for matched source
routing and 0.661/27.6 s for ETX and fixed-SF ETT. The paired MeshEcho
minus source-route ACK-PDR difference is +0.218
(95\% CI [+0.041,+0.395]); the destination-PDR interval includes zero.
Unconditioned random pairs and a 100-node, 3--5-hop case retain an ACK-PDR
advantage over ETX, but at a small airtime cost. Temporal block fading with
short route TTL moves MeshEcho to 0.324 ACK PDR and 71.3 s airtime, so route
aging is a boundary diagnostic rather than a universal claim. The evidence
supports a bounded source-confirmed-reliability--airtime operating point in
simulation, not topology-independent dominance or hardware validity.
\end{abstract}

\begin{IEEEkeywords}
LoRa mesh, Internet of Things, route admission, packet delivery ratio,

\section{Introduction}
LoRa is attractive for low-power IoT because it combines long link budget
with inexpensive radios \cite{augustin2016study}. A star topology is
insufficient for obstructed or infrastructure-poor deployments, motivating
multi-hop extensions \cite{wong2024multihop,cotrim2020lorawanmesh,
centelles2021beyond}. Multi-hop forwarding is expensive: a low data rate
occupies the channel for a long time, while a flood multiplies collision
opportunities. A cached source route reduces redundancy, but one weak hop can
invalidate an otherwise useful path.

MeshEcho records lightweight link-quality evidence during discovery, ranks
candidate paths by confidence, and invokes bounded recovery only when a
route is uncertain. The contribution is not a new link metric; it is an
explicit policy that couples confidence-based admission, a matched
discovery budget, and bounded recovery, then tests that policy against
shortest-candidate, ETX, ETT, and flooding baselines. The implementation is
a simulation prototype, not a production mesh stack.

This paper makes four contributions:
\begin{itemize}
\item a reproducible packet-level LoRa mesh harness with time-on-air,
propagation, shadowing, half-duplex collision/capture, route discovery, and
energy accounting;
\item a per-seed quality-gated, non-saturated ICC matrix with matched
candidate exposure and paired confidence intervals;
\item MeshEcho-only component attribution, a distinct min-hop baseline, and
random-pair, deep-multihop, and temporal-fading generalization evidence; and
\item an explicit boundary separating source-confirmed completion from
destination delivery, cache-aging diagnostics, and simulation-only validity.
\end{itemize}

\section{Related Work}
Prior ICC LoRa studies include analytical and simulation work on coverage,
spreading-factor allocation, and frame error rates
\cite{tu2020coverage,georgiou2020coverage,amichi2019sf,hamdi2020dynamic,
afisiadis2020fer}, as well as testbed validation
\cite{to2018lorans3,rochester2020lsc}. Multihop studies expose the
flooding--airtime tradeoff \cite{wong2024multihop,centelles2021beyond} and
show that routing state and packet timing matter
\cite{sole2022implementation,pueyo2024minimalistic}. ETX is a standard
expected-transmission metric \cite{decouto2003etx}; our fixed-SF ETT row is
a sanity baseline because constant packet time-on-air makes it numerically
coincide with ETX. We therefore ask a narrower question: does confidence
admission change the reliability--airtime operating point under one shared
packet model?

\section{Protocol and Model}
\subsection{Network model}
Nodes are uniformly placed in a square and share one half-duplex LoRa
channel. Unless noted, packets have 32-byte payloads, 17 dBm transmit power,
125-kHz bandwidth, coding rate 4/5, capture threshold 6 dB, and SF7. Airtime
follows the standard LoRa symbol calculation \cite{semtech2013lora}.
Log-distance path loss with log-normal shadowing produces SNR; reception is a
logistic function of SNR margin, and overlapping packets are accepted only
when the desired signal passes capture. The simulator records collisions,
route-cache events, discovery success, and configured TX/RX energy.

\subsection{Routing policies}
Managed flooding rebroadcasts with duplicate suppression. Matched
source-routing floods a request, collects all destination replies arriving in
a 2-s window, and selects the shortest returned candidate. ETX and ETT use
the same discovery and forwarding machinery but minimize
\[
C_{\rm ETX}=\sum_i p_i^{-1},\qquad
C_{\rm ETT}=\sum_i {\rm ToA}_i p_i^{-1},
\]
where $p_i$ is the observed per-hop PRR. The min-hop baseline ignores link
quality after equal candidate exposure. MeshEcho selects the candidate with
the highest confidence, using path length only as a tie-break; a 0.025
per-hop penalty and a linear age penalty (maximum 0.1) are applied to the
confidence score. If no usable route is admitted, a bounded two-hop fallback
is allowed. The ICC runs disable adaptive timeout retries. The historical
Smart-CALM firmware/simulator namespace remains in the repository but is not
an ICC protocol, ablation, or conclusion.

\section{Experimental Design}
\subsection{Primary matrix and metrics}
The primary matrix has 50 nodes in an $8250\,\mathrm{m}$ square, 600-s runs,
mixed traffic at one flow/min, SF7, 4-dB shadowing, and 20 seeds. For each
seed, 24 source--destination pairs are selected from a shared analytical
graph with edge PRR $\geq0.90$ and graph distance 2--4 hops. The quality gate
requires a complete pair pool, mean graph distance at least 2, and at least
10\% of direct links below 0.99 PRR. In this calibrated graph every selected
pair is exactly two hops and all primary route-cache-hit counts are zero.
Thus the headline estimand is first-discovery route admission, not general
cache reuse. All protocols share node placement, traffic, shadowing,
reception streams, discovery window, and route TTL. Reported intervals are
two-sided 95\% paired CIs computed from seed-level differences.

\subsection{Generalization strata}
Three separate 20-seed strata avoid pooling different estimands. Random pairs
use 50 nodes in an 18-km square with mixed traffic at 4 flows/min. Deep
multihop uses 100 nodes in a 21-km square, unicast at 2 flows/min, and
24 pairs selected at graph distance 3--5; the 21-km calibration was chosen
before the final run because the 20-km setting failed the complete-pool gate
for seed 12. Temporal-fading cases reuse four connected pairs in the
8.25-km square with 6-dB block fading every 60 s, comparing 600-s and 30-s
route TTLs. These cases report limits and are not pooled with Table~\ref{tab:main}.

\section{Results}
\subsection{Primary and mechanism evidence}
MeshEcho improves over matched source routing by +0.218 ACK PDR
(95\% CI $[+0.041,+0.395]$) and reduces airtime by 10.3 s
($[-12.6,-8.1]$). Destination PDR changes by +0.103
($[-0.086,+0.292]$), so the strongest claim concerns source-confirmed
completion under the simulator's reverse-path ACK model. MeshEcho versus
ETX/ETT is +0.059 ACK PDR ($[-0.108,+0.226]$), and versus min-hop is
+0.301 ($[+0.161,+0.441]$); the latter is a distinct shortest-path
baseline, not an oracle.

The no-confidence row is an end-to-end policy-bundle comparison: discovery
success, candidate count, and route length also change. The controlled

selects the longer branch in every observed conflict and improves ACK PDR by
$+0.221\pm0.096$ over shortest-candidate selection. This supports candidate
admission in that controlled topology, not a universal confidence advantage.

Random pairs retain an ACK-PDR advantage over ETX while removing fixed-pair

lowest-airtime policy. Under temporal fading, shortening the TTL increases
repair and airtime for every routing policy and reduces MeshEcho to 0.324
ACK PDR. The fading results therefore define a stale-route boundary rather
than proving that confidence aging solves time-varying channels.

\subsection{Sensitivity and stress cases}
At SF8, MeshEcho reaches 0.405 ACK PDR/61.7 s, while managed flooding reaches
0.434/39.2 s. At four flows/min, MeshEcho reaches 0.660/111.0 s versus
0.450/107.6 s for ETX and 0.409/50.5 s for flooding. These are operating
points, not universal rankings. The 18-km, 3-seed quality probe passes its
pair and link gates but has only 0.178 MeshCore-like discovery success; it is
reported as a route-discovery stress diagnostic, not a neutral data-plane
comparison.

\subsection{Fairness and metric boundaries}
The matched source-route baseline collects every destination reply arriving
within the same discovery window as MeshEcho, so the primary contrast is not
an immediate-reply versus delayed-reply artifact. The protocols nevertheless
retain different forwarding and recovery semantics by design. We therefore
report both ACK PDR and destination PDR: an ACK confirms source-side
completion, whereas destination PDR can remain high when the reverse path
fails. Airtime includes discovery, data, ACK, and recovery transmissions, so
the reported operating point does not hide control cost.

\section{Discussion and Limitations}
The evidence supports a bounded claim: in the calibrated shared harness,
MeshEcho improves the source-confirmed reliability--airtime operating point
over matched source routing, while ETX/ETT remain statistically
indistinguishable in the primary comparison. Managed flooding remains the
low-airtime reference, and the min-hop/deep/random strata show that the
confidence policy is not an automatic dominance result. Cache reuse and
temporal fading are secondary diagnostics: the 600-s versus 30-s cache
experiment moves MeshEcho from 0.786/25.7 s to 0.472/88.5 s, with route
repairs rising from 0.25 to 18.5 per run. These values are not pooled with
the zero-hit primary estimand.

All results are packet-level simulation. The model includes path loss,
shadowing, collision timing, capture, route discovery, and energy accounting,
but omits waveform interference, oscillator offset, modem implementation
timing, duty-cycle enforcement, variable route headers, and antenna effects.
The confidence estimate and forwarding channel share the same realization in
static runs; temporal block fading is a deterministic stress model, not
hardware validation. A hardware or hardware-in-the-loop study remains
necessary for radio-specific external validity.

\subsection{Threats to interpretation}
The quality gate is deliberately a measurement contract, not a guarantee of
deployment realism. Pair selection from an analytical PRR graph removes
degenerate disconnected samples, but it conditions the primary estimate on
links that are usable in the static model. The random-pair stratum removes
that conditioning at the cost of lower route completion, and the deep stratum
tests a different scale and hop distribution. We report all three rather than
averaging them into a single ranking.

The paired design shares topology, traffic, and reception streams, but it is
not event-by-event common-random-number coupling: protocols transmit
different numbers of packets and therefore encounter different collision
histories. Confidence intervals are computed from independent seed-level
differences, not from individual packets or flows. This avoids overstating
precision while preserving the topology pairing. The no-confidence ablation
also changes discovery success and route length, so it is a policy-bundle
contrast, not a fixed-candidate causal estimate. Finally, the route-conflict
audit has only seven nodes and is intentionally surgical; it cannot replace a
random-topology comparison.

These boundaries determine what a future hardware study must preserve:
the same pair schedule, discovery window, source-confirmed and destination
metrics, airtime accounting, and route-TTL perturbation. A small SX126x or
SX127x testbed with RSSI/SNR logs would test whether the simulated confidence
ordering survives oscillator, antenna, modem-timing, and duty-cycle effects.

\section{Reproducibility}
Version 2.1.22 releases source, tests, raw seed-level CSVs, summary CSVs, and
Markdown reports. The main workflow is
\texttt{OUT\_PREFIX=meshecho\_v2\_1\_22\_icc2027 bash
tools/run\_icc\_experiments.sh}. The sensitivity, generalization, cache, and
route-conflict commands are versioned in
\texttt{tools/run\_icc\_sensitivity\_experiments.py},
\texttt{tools/run\_icc\_generalization\_experiment.py},
\texttt{tools/run\_icc\_cache\_experiment.py}, and
\texttt{tools/run\_route\_conflict\_experiment.py}. No human participants or
personal data were involved; there are no known conflicts of interest or
external funding.

\subsection{Evidence manifest}
The released artifacts keep raw observations separate from interpretation.
The primary and sensitivity CSVs contain one row per protocol and seed; the
generalization runner writes one file per estimand; and the Markdown reports
record link quantiles, pair-selection rules, route-hop diagnostics, discovery
success, and paired comparisons. The versioned component file contains only
the MeshEcho policy variants, so a historical adaptive-firmware result cannot
silently enter the ICC table. The quality gate is run before a connected
multihop CSV is accepted, and its failure messages identify the seed and the
violated condition. This separation makes it possible to reproduce the
headline matrix while independently auditing selection, cache reuse, and
temporal fading.

\subsection{Audit checklist}
Before interpretation, the release checks the protocol registry, the
candidate-exposure window, the route-TTL setting, and the independent channel
stream. The calibrated and sensitivity runners reject incomplete connected
pair pools before writing reports. The generalization runner records the
selection rule for every stratum and reruns all protocols on the same seed
and topology. The temporal-fading implementation derives its perturbation
from the unordered link, seed, and time block, so protocol event ordering
cannot change the fading realization. The cache diagnostic reports both
route-cache hits and route repairs; the route-conflict audit records the
selected path and both candidate confidence values. These checks are useful
because a high aggregate PDR can otherwise hide a mostly one-hop or
route-discovery-limited experiment.

The raw CSV schema also preserves negative and boundary cases. Managed
flooding can have high destination PDR but low ACK PDR; ETX and ETT can
coincide under fixed SF; min-hop can select a shorter but less reliable
candidate; and MeshEcho can spend more airtime when confidence admission
chooses a longer path. We retain these rows in the released summaries rather
than replacing them with a single rank score. The paper's numerical claims
are generated from the Markdown reports, while the CSVs remain the authority
for seed-level recomputation and alternative confidence intervals.

\section{Conclusion}
MeshEcho reaches 0.720 ACK PDR at 28.1 s in the calibrated multi-hop
simulation, compared with 0.502/38.5 s for matched source routing and
0.661/27.6 s for ETX/ETT. Random-pair and deeper-hop cases preserve the
direction of the ACK-PDR result with a small airtime cost, while temporal
fading and short TTLs expose a clear stale-route boundary. Component and
route-conflict evidence implicate confidence-aware candidate admission as the
main effect in this workload. Version 2.1.22 therefore supports a
reproducible, bounded MeshEcho simulation claim, not topology-independent
dominance or physical validation.
